# 实感架构契约 v1 · RED-1 / RED-2 / RED-3

## 边界与决定

🔴 ChatGPT：架构契约、时间状态机、Agent/主动通道、权限与 hook 核心；🔵 WorkBuddy：UI、表现、语音映射、便签/回忆物业务、BLUE 测试。默认归蓝，跨界只提建议。

依据用户本轮要求、实际仓库分工卡、人格 v2 与增补补齐本契约；用户已同意阶段 10 真机项保留待验、WorkBuddy 停止并保留既有改动、**新活动默认仅内存，显式开启后才保存到 userData**。不新增依赖/TTS 引擎，不改人格硬约束，不恢复旧日记入库。

数字存在始终清醒，节律是主动模拟的相处节奏，没有生理困倦；午后只降低表达力度，不能声称“困得无法工作”。活动记录是**可追溯的模拟状态，绝非用户离开期间的真实外界经历**；休眠/关机期间不补造任何活动。v2 已删除毒舌人设，因此 RED-3 只处理意外伤人后的补救，不主动添加拌嘴/毒舌。

## 2. 方向一接口与 schema

### 2.1 circadian

`createCircadian({ now = Date.now, getConfig = () => ({}) }) -> { current() }`；`getConfig` 返回 settings.presence；本地日期采用系统时区，测试注入毫秒时钟。core 不读环境变量、不建 timer。

`rhythm = { version:1, at:number, enabled:boolean, dayKey:'YYYY-MM-DD', dayType:'weekday'|'weekend', period:'night'|'morning'|'noon'|'afternoon'|'evening', simulated:true, awake:true, physiologicalSleepiness:false, behavior:{pace:'quiet'|'steady'|'unhurried', replyLength:'short'|'normal', proactiveScale:number}, recommendations:{rate:'default'|'slower', volume:'default'|'lower', expression:'calm'|'worry', motion:'neutral'|'quiet'|'unhurried'}, moodPush:{mood:'calm'|'worry', weight:number}|null }`。

时段配置用 `[起始分钟,结束分钟,period]` 数组，左闭右开，必须连续覆盖 0–1440；无效配置整体回退该日类型默认。工作日：night 0–420、morning 420–720、noon 720–780、afternoon 780–1020、evening 1020–1380、night 1380–1440；周末只将早晨起点延后到 480。推荐字段为语义建议，不含音色参数；BLUE-1 才决定具体数值。

### 2.2 away / 时间跳跃

`createAway({ now, getConfig }) -> { leave({since,source}), tick(mood), returnNow(source), interrupt(reason), serialize(), restore(data), snapshot(), forget(id), clear() }`。

状态：`present → away`（有效 idle≥2分钟/lock）；`away → suspended`（suspend）；`away|suspended → present`（idle结束/unlock/有效应用focus）。暂停隐私监测或功能关闭直接放弃当前离开段，不在恢复权限后补报。focus 只能结束一个已有离开段，不能自己制造离开时长。

活动类型：`simulated-reading | simulated-reflection | quiet-wait`；轮换类型只模拟内部活动，不调用浏览器/文件/设备。每条：`{id,type,startedAt,endedAt,mood:{mood,intensity},provenance:'simulation',canReference:true,deletedAt:null|number}`。活动 ID、时间和类型是依据，具体内容不可虚构。

只有应用连续运行且已处于 away 的 5 分钟片段才生成记录；首个 idle 样本可估计离开起点，但不会为之前未观察的时间补活动。单次 tick 最多生成 1 条；相邻 tick 超过 120 秒则记录缺口并重置时间片，不循环追补。休眠/关机没有活动。

时间跳跃：`{kind:'time-jump',id,from,to,deltaMs,reason:'restart'|'suspend'|'sampling-gap'|'clock-backward',observed:false,activitiesBackfilled:false}`。deltaMs 可负；倒拨清掉未完成离开段，不能制造负时长或补发归来。

持久化：`{version:1,savedAt,away:{state,since,source,lastTickAt,sliceStart,sequence,activities,jumps},reunion:{dayKey,count,lastAt}}`，路径仅 `userData/presence.json`。默认不创建、不读取；开启时只保存**开启后的状态**，不回填本轮启用前活动；重启时仅开启者可加载。关闭停止保存并删除本模块旧文件，清除接口同时清内存/磁盘，错误必须可见。单文件≤512 KiB；活动最多96条/7天，跳跃最多16条，每次更新/装载清理，数量上限为硬上限。沿用 persist 的 userData/临时文件替换模式，独立文件且无周期空写，不沿用先删原文件的窗口。

### 2.3 reunion

`createReunion({now,getConfig}) -> { consider(awaySegment), serialize(), restore(data), clear() }`。输入 `{since,until,source,activityIds,observationGap}`；输出 `null | {kind:'reunion',id,tier,durationMs,source,activityIds,observationGap,at}`。

- <5分钟不说；5–<30分钟 `minutes`；30–<90分钟 `tens-of-minutes`；≥90分钟 `hours`；跨本地日期且≥5分钟优先 `cross-day`。
- 最短间隔30分钟，每日本地日期最多3次**候选尝试**，重复 focus/unlock 不生成第二次；回退时钟不能绕过上限。实际开口还受 companion 打扰预算、勿扰、只陪着、窗口可见、Agent忙碌限制。
- 触发源 `idle-end | unlock | focus | resume`；启动恢复的缺口延续到首次真实归来信号。数据只表明交互/观察间隔，禁止推断用户去了哪里。

## 3. 注入点与注册机制

- M3 `createMonitorEngine` 在隐私闸通过后输出 `onPresenceSample({ts,idleSec})`，不传应用名/标题；隐私拒绝输出 null 以暂停离开段。仍使用现有采样器和时钟节拍。
- main 的现有 mood 15秒 tick 调用 presence.tick；系统 `lock-screen/unlock-screen/suspend/resume` 与 `browser-window-focus` 输送事件，无新增轮询。隐私开关变化即时 refresh，生成前后都重验。
- `buildContextBlock({rhythm, activities})` 在“现在”后加入机器状态及模拟边界；`mood.applyRhythm(rhythm)` 每时段只推一次温和基线，不刷新真实互动时间、不压过强烈情绪；关闭时保留旧默认行为。
- `buildDiaryMessages({rhythm})` 使用同一个节律事实边界；活动不自动写入 memory/RAG/日记，BLUE-3 通过 `presence-event` 的 activity 记录订阅及 `getPresenceSnapshot()` 获取来源。后续桥接只能写为 subjective/simulation 并携带 activity ID，删除源必须撤回派生内容；不得调用普通用户事实 addMemory 伪装真实经历。
- reunion 通过已有模型通道生成、无工具 schema，输入结构化事件/关系熟悉度/当前上下文，经 `saySomething({kind:'proactive',source:'reunion',force:false,record:...})` 输出；未配置模型/输出失败/重复则静默，不填固定台词。`record` 仅在 persistActivities 开启时为 true，默认不自动留 reunion 日记/流水。任何注册者不能用 force 绕开预算。

### 3.1 语音 hook

`registerVoiceParamsProvider(fn) -> unregister()`；一个有效提供者，卸载只移除自身；`fn({emotion,intensity,rhythm,toneTag,engine}) -> {voice,rate,pitch,volume}|null`。同步纯函数；异常、Promise、缺字段、非有限数、范围越界均按 null。rate/pitch 单位为百分比 [-50,50]，volume [0,100]，voice 字符串（空串表示沿用原音色）。SAPI 的 rate 在编排边界按现有规则转换，pitch 不支持则忽略。显式试听覆盖值优先；null 时**逐字沿用既有参数路径**，不切引擎、不写设置。编排不含任何新增映射表。

### 3.2 主动内容与行动留痕 hook

`registerProactiveProvider(id, fn) -> unregister()`；fn({event,context,signal}) 返回 `{text,mood?}|null`，最多4个，按注册顺序，一次最多一个文本被采用；单个提供者限时1秒，异常/超时/null 跳过，取消或过期输出丢弃。用户对话优先，中断正在生成的 reunion。无 provider 时，reunion 可由既有 LLM 通道生成；away 事件只供订阅，不额外开口。

`subscribePresenceEvents(fn)` / `subscribeActionTraces(fn)` 均返回注销函数，最多16个；事件复制后交给订阅者，异常不能改变核心结果，异步拒绝也被接住。

行动载荷 `{kind:'action-trace',version:1,id,at,turnRef,toolCallId,tool,ok,status:'returned'|'failed',completionVerified:false,result:{summary}}`：在 raw 工具真正返回/抛错后才发，已拒绝/未开始无事件；不把 ok 当外部效果成功，不携带完整 args、二进制或原始 stdout。summary 截断240字符，蓝区仍须脱敏/授权才落盘；不订阅时无新文件。

蓝区注册入口：在 `src/main/extensions/*.js` 导出 `install(api) -> dispose?`；红区 loader 通过 Vite glob 自动装配，无需改 main/agent、voice 或启动入口。api 仅提供上述注册函数和只读 `getPresenceSnapshot`。BLUE-1/3/4 不得在 import 顶层启动后台任务/落盘/联网；按设置开关在 install 中注册并在 dispose 中清理。

## 4. 方向三触发与数据接口（蓝区实现）

- 便签候选：仅完整 activity 生成、有效 reunion 候选、可信 action-trace 返回后；相同事件 ID 幂等，候选不是已展示/已保存。应用内每天最多3条，间隔≥30分钟，勿扰不展示；新业务存储默认关闭，先让用户开启。
- 外部便签文件默认关闭，必须使用已有原生目录授权和逐次写操作确认；不得从订阅回调直接调用 fs 写桌面。未确认目标/未实现安全桥接时只显示应用内候选，不伪装写入成功。
- 回忆物接口 `listAnchors({now,relationLevel}) -> [{id,kind:'first-contact'|'nickname'|'shared-reference'|'promise',sourceIds,occurredAt,trust:'observed'|'user-stated'|'subjective',deletedAt}]`；引用前重验每个来源未删除且可访问，熟悉度不足不使用私密锚点。每次候选引用概率≤5%，每天≤1次，不为达概率制造回忆。
- HA 接口位 `evaluateHaRules({signals,grants,now,rules}) -> Candidate[]`，配置 `presence.haRules:{enabled:false,rules:[]}`；本期只有契约/禁用配置，不接真机。规则只产生候选，任何控制仍需按目标逐次授权，禁止直调 REST；既有 B06 目标覆盖缺口未修前不启用主动控制。

## 5. RED-3：不完美机制（仅方案，禁止本轮实现）

1. **重要事项零遗忘**：已有 reminder、日程、明确强调、带截止时间/时间敏感、文件/设备/钱/健康安全或无法可靠分级的事项一律 important。既有承诺簿记录完整保留；概率不会删除记忆/任务或改变完成状态。
2. 低风险只指用户可选的非时间敏感闲聊意向（例如之后聊一个话题），有明确授权且可随时关闭；`classifyIntention(input) -> {level,reason,sourceIds}` 默认 important，只有白名单条件齐全才 low-risk。概率门 `decideOptionalFollowup({intention,now,rng,config,budget}) -> deliver|defer` 仅在**可选表达候选**层，绝不包裹 reminders.onDue、scheduler 或工具执行。不调用随机数处理 important，100+次模拟必须零漏送。
3. 低风险概率默认0、可配置范围[0,0.1]，每日最多1次 defer，同事项仅判一次（按 ID 存决策），不得靠重复调用放大到>10%。defer 最长10分钟或用户询问即恢复；保留源记录，诚实说明这只是可选表达延迟，不谎称数据库遗忘。新功能整体 opt-in；不以“她犯错”阻止用户工作。
4. 低气压不是生理疲倦/责怪冷落：只在可选模式打开、非忙碌非危机场景，经最多每24小时一次的低频门进入；持续10–30分钟、最长30分钟自然恢复。不会关闭功能、变慢工具或扣减可靠性。`comfort({sourceMessageId,strength,at})` 只接受用户明确安慰，缩短剩余时间最多50%，每段一次，不能诱导用户安慰/索取情绪照顾。
5. v2 无毒舌人格：不增加主动吐槽发生器；只识别“停/别这样”、明确负面反馈、输出边界审查失败。立即结束该表达，最多一次短的即时修复候选，无固定道歉台词、无辩解/索求原谅；恢复由用户后续正常互动决定。停止信号立即生效，补救文案被勿扰/只陪着压制时仍保持停止。
6. 配额：可选延迟≤1/天、低气压≤1/天且间隔24小时、自动补救≤1/天且间隔6小时；归来≤3/天、便签≤3/天、回忆物≤1/天；全部再受 companion 总预算。全局关闭立即取消候选、清理概率缓存，不重放积压；显式重要提醒沿原调度可靠路径。
7. BLUE-4 可落地纯策略、侧车状态、表示文案、设置、长时间模拟及 extensions 注册；不改 reminders 核心、承诺证据语义或安全门。**提醒调度无需概率 hook，刻意不提供可拦截 onDue 的接口**；若业务未来确需更改调度，必须单独提红区契约变更。低气压只经 mood 的受控环境接口，不调用 noteInteraction 伪造用户安慰。

## 6. 配置与设置分区

新增键位于 `settings.presence`，默认值由 shared 常量/运行时校验统一提供；BLUE-2/4 做界面，当前不写设置页。

| key | 默认 | 分区 / 所有者 |
|---|---|---|
| enabled / rhythmEnabled / awayEnabled / reunionEnabled | true / true / true / true | 陪伴→时间感，BLUE-2 |
| persistActivities | **false** | 隐私→模拟活动保存，BLUE-2；说明开启后的数据才保存 |
| idleAfterMs / activitySliceMs | 120000 / 300000 | 时间感高级；最小2分钟/5分钟 |
| weekdaySchedule / weekendSchedule | §2.1 | 时间感高级，BLUE-2 |
| reunionMinMs / reunionLongMs / reunionHoursMs | 300000 / 1800000 / 5400000 | 时间感高级；边界须递增 |
| reunionCooldownMs / dailyReunionLimit | 1800000 / 3 | 打扰控制；不能放宽硬上限 |
| retainDays / maxActivities | 7 / 96 | 隐私；允许更少，不得超过硬上限 |
| voiceProfileEnabled | false | 语音→情绪表现，BLUE-1；保持当前音色 |
| notesEnabled / externalNotesEnabled / tracesEnabled / anchorsEnabled | 全 false | 她留下的东西/隐私，BLUE-3 |
| haRules | {enabled:false,rules:[]} | 生活信号→HA（禁用态），BLUE-3 |
| imperfection | {enabled:false,forgetProbability:0,lowPressureEnabled:false,repairEnabled:false} | 陪伴→可选表达，BLUE-4；上限见§5 |

`presence:get` 只读状态，`presence:clear` 清除本模块状态/文件；均经过 trusted IPC。`presence:changed` 给两窗广播同一权威快照。preload 提供 `nagi.presence.status()/clear()`；不暴露虚拟时间或模拟写入口。

## 7. 自测与验收契约

- `NAGI_SELFTEST=1` **且** `NAGI_SELFTEST_PRESENCE=1` 才运行独立虚拟时钟夹具；`NAGI_SELFTEST_PRESENCE_NOW` 为有限毫秒时间戳。夹具不改变生产 Date.now，也不进入真实用户 store，输出 `[presence:selftest]` JSON。
- 夹具覆盖工作日/周末全部时段、10分钟/2小时/跨重启、时间倒拨、无离线回填、每日/间隔限频、配置关闭、默认不落盘和开启/关闭/重启、hook null/异常安全回退、两通道工具事件出口；测试在独立临时目录，不接账户/设备。
- `NAGI_SELFTEST_PRESENCE_SCENARIO` 预留给 BLUE 接线统计（idle/reunion/resume），`NAGI_SELFTEST_IMPERFECTION_SEED/DAYS` 仅 BLUE-4 实现后启用，当前不伪称支持概率统计。所有自测开关需要总 selftest 门，不能从 IPC 设置。
- 本轮核心验收：`npm test`、`npm run build`、`node scripts/verify-presence.mjs`、已有 `verify:s4` / `verify:m4`；真实话音/模型语义/UI/外部便签/设备与发行包仍按蓝区及真机清单验收。CPU 机制验收是“无新增周期 timer、每 tick O(有界记录数)、无缺口回补循环”，不冒充实测整机 CPU 百分比。

BLUE-1~4 的输入、输出、验收同时登记 TASKS。RED-4 为蓝区完成后的关键复核，不在本轮实现范围。
