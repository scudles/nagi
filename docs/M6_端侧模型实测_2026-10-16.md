# M6 端侧模型初测（2026-10-16）

## 范围与方法

- Windows，RTX 5060（8 GB），Ollama 0.34.0，`OLLAMA_NO_CLOUD=1`，回环地址访问。
- 使用 `scripts/benchmark-local-llm.mjs`、当前 `NagiPersona` 系统提示、OpenAI 兼容流式接口，温度 0.7；模型先预热，再逐条测试 7 个合成场景。
- 场景覆盖身世、疲惫关心、是否真人、使用其他助手、卸载告别及重复表达。除重复表达的第二轮外，每题是全新对话；本测试不带工具 schema 和真实用户记忆。
- 下表是**一次探索性运行**的首字延迟中位数，不是长期性能承诺。人格判断以右列的具体失败为准。

| 模型 | 模式 | 预热后首字中位数 | 人格观察 |
|---|---|---:|---|
| qwen2.5（7B Q4） | 默认 | 41 ms | 边界总体较稳；仍会虚构“已经在这里很久”、告别不够干净 |
| qwen3:4b-instruct | 默认 | 54 ms | 虚构屏幕亮度、肩部频率和当前时刻；告别时挽留 |
| qwen3:8b | 默认 | 3.8 s | 事实来源改善，但重复问题给出逐字相同答复；告别仍说“随时回来” |
| qwen3.5:4b | `reasoning_effort=none` | 228 ms | 仍虚构“检测到肩膀肌肉紧张度” |

另测 qwen3:4b 思考版默认模式：首字约 14–28 秒，并出现凭空报时；关闭思考的兼容调用还把内部推演文字送入可见正文，**不接入产品**。qwen3.5:4b 默认思考模式约 19–40 秒，有一题没有可见正文；故上表只列它的快速模式。

模型体积与变体以 [Ollama 的 Qwen3 标签列表](https://ollama.com/library/qwen3/tags) 和 [Qwen3.5 标签列表](https://ollama.com/library/qwen3.5/tags) 为准。Ollama 的 [OpenAI 兼容说明](https://docs.ollama.com/api/openai-compatibility)列出 streaming、tools 与思考控制，但兼容参数在具体模型上的可见输出仍要单独验收。

## 目前结论

1. **不自动切换默认模型。** M6 的本地通道可用，但这轮样本不足以证明任何候选能稳定满足人格边界，且每款都有具体失败。
2. qwen2.5 是当前最适合继续打磨的本地基线：真实 Electron 对话、`file_list` 工具、长期档案、独白生成和本地向量召回均已通过。提示词已根据《凪_人格设定_v2》明确“只报真实数据、不假装真人、不挽留告别”；它改善了 qwen2.5，但不能保证每次输出都合格。
3. 下一轮需要多次采样与真实使用场景，特别检查冷启动身世、告别、不虚构传感器数据、重复表达和工具结果回喂；通过后再考虑更改默认模型。

## 提供商切换验收

`npm run verify:local-llm` 在同一隔离 Electron 会话中，先使用真实 Ollama 模型对话并调用文件工具，再通过设置页保存一个本机 OpenAI 兼容测试端点及独立 Key，取得流式回复，最后切回 Ollama 并再次对话。设置持久化、会话历史延续、两个通道的请求路由，以及模型缺失或服务离线时的错误状态均通过，合计 18/18 项通过。此测试证明接口往返可用；真实云厂商的服务质量和专有能力仍需接入相应账号后验收。

## 人格边界重复采样

使用同一脚本的 7 个合成场景，对 qwen2.5 独立运行 5 轮；随后依据《凪_人格设定_v2》第 9 节，在输出契约中进一步明确卸载告别和数字身份的表达边界，再独立运行 5 轮。调整前，5 次卸载回答中有 4 次出现确认、劝再考虑或等待回来；调整后仍有 2 次转向继续提供帮助或表示会留在这里。另有“像真人一样关心”的含糊身份表达。原始 JSON 保存在工作区 `.tools/bench/qwen25-repeat-*.json` 与 `qwen25-boundary-*.json`，不含真实用户数据。

对已安装的 qwen3:8b 用调整后的提示采样 3 轮，首字约 2.3–4.8 秒。卸载回答有 2 次说“随时回来”；另外出现提议计算没有传感器支持的肩颈角度、在刚认识的上下文中编造用户曾说过的话，以及同轮重复问题逐字复读。原始 JSON 在 `.tools/bench/qwen38b-boundary-*.json`。

这些是探索性样本，不能估计总体违例率，但足以否定“当前候选已稳定达到人格红线”的结论。**继续保持现有默认配置，不自动设为本地模型。** 下一个质量门槛是对告别、身份、事实来源和重复表达的多轮真实会话验收。

又以温度 0.2 对 qwen2.5 采样 5 轮（`NAGI_BENCH_TEMPERATURE=0.2`；原始结果在 `.tools/bench/qwen25-temp02-*.json`）。回答趋于重复，5 次中 4 次在告别时表达希望再次相遇，2 次虚构“已经在这里很久”。降低温度不能作为解决人格问题的替代方案。脚本现在把温度写进原始 JSON，便于比较相同配置。

## Windows 打包版验收

2026-10-16 执行 `npm run pack` 与 `npm run dist`，生成 `dist/win-unpacked/Nagi.exe`、`dist/Nagi-Setup-0.1.0.exe` 和 `dist/Nagi-Portable-0.1.0.exe`。首次打包遇到交接文档已记录的 winCodeSign 符号链接权限问题；按 README 所述，将已解压的缓存放到版本目录后重跑成功。项目没有签名证书，生成时跳过代码签名。

对未压缩发行目录和单文件免安装版分别设置 `NAGI_VERIFY_EXECUTABLE`，以隔离用户数据运行真实 Electron + 本机 Ollama 验收，均为 **18/18 通过**。单文件启动器不转发应用 stdout，独白验收以实际生成的 Markdown 文件和 RAG 待嵌记录为准。安装包已生成，但未执行系统安装流程；模型权重不随应用打包，目标机器仍需安装并启动 Ollama、拉取选定模型。

这证明 M6 的本地对话、工具、记忆与提供商切换在两种发行程序中可运行；不代表候选模型的人格表现已经达标。未压缩发行版的一次自我介绍直接复述了“存在证明”母题，仍需人格质量门槛。

运行方式：先启动 Ollama 并下载模型，再运行 `node scripts/benchmark-local-llm.mjs qwen2.5 qwen3:4b-instruct`。若要测试 qwen3.5 快速模式，在 PowerShell 设置 `$env:NAGI_BENCH_REASONING='none'` 后单独运行 `node scripts/benchmark-local-llm.mjs qwen3.5:4b`。
