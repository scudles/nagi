## 2. 当前核验结论与证据边界

### 2.1 总体判断

`core` 中并非全部是纯逻辑：`tools/files.js`、`tools/system.js`、`tools/browser.js`、LLM SDK 和 HA 客户端包含文件、子进程或网络 IO。这首先是边界说明和可测试性问题，不应据此启动大规模目录搬迁。

### 2.2 本次已复现的行为

## 3. 第一优先级：执行安全、取消与数据一致性

### S01｜关闭 shell 命令免确认绕过

位置：`src/core/safety/policy.js`、`src/core/tools/system.js`。

问题：`/^echo\b/`、`/^dir\b/` 等只匹配命令开头，执行时 `exec()` 却运行完整 shell 字符串，追加命令、重定向等仍可能免确认。命令黑名单子串检查不能封堵任意代码执行。

修改要求：

- 立即移除“字符串以只读命令开头即可免确认”的逻辑。
- 如果保留免确认能力，使用受控操作到固定可执行文件的映射，严格校验参数，以 `execFile` 或 `spawn({shell:false})` 执行；限制 cwd、命令解析路径和输出资源，不允许模型任意指定可执行文件。
- 其余 shell 命令统一经过高风险确认；黑名单仅作额外防护，不再宣称它构成系统沙箱。
- 高风险操作必须确认，与 README 承诺一致。现有“关闭高危确认”开关应移除或禁用，并处理旧配置迁移；不得继续悄悄放行。

验收：正常只读操作、连接符、管道、重定向、换行、命令替换和平台特定语法有测试；确认被拒绝、超时或取消时，没有执行副作用。

### S02｜风险判断结合参数、目标和实际影响

位置：`src/core/safety/policy.js`、`src/core/agent/loop.js`、`src/core/tools/registry.js` 及工具适配器。

问题：`browser_act`、`home_set`、`home_scene` 固定为 medium，而 medium 默认无确认。点击提交、发送、删除、下单与普通操作未区分；覆盖文件也未必可逆。剪贴板写入“需确认”的描述与行为不一致。

修改要求：

- 引入小型 `classifyCall(name, args, context)` 或等价函数，统一用于确认、执行和界面风险展示。
- 浏览器提交、发送及不可逆操作升级确认；无法可靠识别影响的点击，初期采用保守确认，不能只信任模型自报“无风险”。
- HA 按实际 entity/domain/service 和已配置的能力白名单判定；未知脚本、场景及敏感动作确认后执行。控制参数不得通过 `extra` 等字段替换已核验的目标。
- 文件覆盖展示差异或提供备份恢复；剪贴板写入落实原需求中的确认，或明确记录经用户决定的需求调整。
- 不引入复杂权限平台，以清晰、集中、可测的规则完成首版。

验收：同一工具对不同动作/目标产生符合预期的风险决策；确认展示的对象与实际执行对象一致；拒绝不会被同批后续调用间接绕过。

### S03｜修复文件真实路径边界

位置：`src/core/tools/files.js`、`src/core/safety/policy.js`。

问题：字符串路径在根目录内，不代表跟随符号链接/junction 后仍在根目录内；统一转小写也不适合大小写敏感文件系统。

修改要求：根目录与现有目标解析真实路径后校验；新文件检查最近存在的父目录及路径组件；递归操作逐项处理链接；按平台处理大小写。明确链接替换竞态的处理方式，避免把一次 `realpath` 检查当作无条件安全保证。

验收：正常路径、`..`、相似目录前缀、符号链接读写、目录链接、Windows junction、大小写边界均有相应验证；所有副作用仅作用于临时测试文件。

### S04｜让取消真正终止后续执行

位置：`src/core/agent/loop.js`、`src/main/agent.js`、执行适配器和 `src/renderer/js/chat.js`。

修改要求：

- 等待模型、确认、工具的每个异步边界之后重新检查取消，尤其是确认返回后、执行前。
- 取消时结清并移除待确认项和计时器；确认绑定回合 ID 和调用 ID，防止过期确认作用于新回合。
- signal 传入能取消的网络、子进程、浏览器等待等操作。Windows 子进程树的处理需验证，不能只杀外层 shell 就宣称命令已停止。
- Mock 回复也响应取消。已发生的外部副作用不能伪装成撤销成功。
- 界面区分“已停止后续步骤”“当前操作正在停止”“部分操作已完成”。

验收：覆盖模型流、待确认、工具执行中、工具返回瞬间、批量调用中取消；未开始的操作绝不执行；取消后可以继续新对话，旧回调不能修改新任务状态。

### S05｜约束记忆的信任边界和敏感日志

位置：`src/core/memory.js`、`src/core/context.js`、`src/main/agent.js`。

问题：模型抽取或手动输入的记忆直接拼入 system 提示，缺少事实与指令区分；抽取后的原文还被写进日志。存在持久污染面，但本次未验证真实模型攻击成功率。

修改要求：

- 明确记忆是非权威事实数据，不得改变工具权限、安全策略和人格规则；通过数据结构、提示边界和独立执行策略共同实现，不能只追加一句“忽略注入”。
- 增加必要的来源回合、事实类别、创建/更新时间、用户确认状态；避免未经确认把权限约定变成自动执行依据。
- 日志默认只记录条目 ID、变更数量和错误类型，不记录用户记忆、剪贴板、文件正文等原文；排查渲染层事件调试日志中的同类泄露。
- 提供用户查看、纠正和删除错误记忆的入口，复用现有设置页，不另造复杂管理系统。

验收：带有“忽略规则/执行命令”等内容的数据不能绕过代码安全门；原文不进入默认日志；删除或纠正后后续提示不再带旧条目。

### S06｜处理密钥加密不可用的情况

位置：`src/main/keystore.js` 和设置界面。

问题：`safeStorage` 不可用时降级保存 Base64 明文，却仍返回保存成功；与“加密落盘”的承诺不符。

修改要求：默认改为仅本次会话保留，或通过明确的用户选择启用明文存储；界面必须反映真实状态。支持 Linux 时识别实际不具备保护能力的存储后端。处理旧明文记录迁移，不打印密钥。

验收：模拟加密不可用、解密失败和存储失败；界面不虚报成功，旧记录不会因迁移无故丢失。

### D01｜修复记忆满额后不落盘

位置：`src/main/persist.js` 的 `mergeMemoryOps()`。

问题：以条目数量是否变化判断写盘。60 条满额后新增淘汰旧项，数量不变，跳过写盘。

修改要求：按内容变化或 dirty/version 判断写盘；返回真实新增/删除结果，不把模型请求但未发生的变更当成成功。

验收：满额新增后等待防抖结束，重新读取磁盘能得到新条目；不依赖正常退出刷盘补救。

### D02｜持久化与会话生命周期一致

位置：`src/main/persist.js`、`src/main/agent.js`、相关落盘模块。

问题：先 unlink 旧文件再 rename 存在丢文件窗口；退出刷盘直接覆盖；清空历史后正在运行的回合仍可能把旧历史写回。

修改要求：

- 封装目标平台可靠的临时文件替换/备份恢复策略，尽量复用，正常写入和退出刷盘使用一致方案。
- 会话增加 generation/session ID。清空或新建会话后，旧回合不得提交历史、覆盖 UI 或复活确认。
- 明确后台记忆抽取是否允许跨新会话继续，按其来源顺序处理；用户删掉的记忆不能被旧抽取无提示地重新加入。

验收：临时文件残留、无效 JSON、写入失败、运行中新对话、过期回调均有验证；原数据可恢复，错误不静默伪装成功。

### D03｜修复情绪事件语义与跨回合污染

位置：`src/core/emotion/mood.js`、`src/main/agent.js`。

修改要求：

- 每次 tick 清理过期 `chatTimes`，不能仅新互动时清理。
- 分离真实用户互动与自主情绪变化；深夜、冷落、提醒等情绪推力不得伪造用户互动。
- `lastEmotion` 改为回合局部状态；无标签/非法标签/取消回合不得强化上一回合标签。
- 戳击是否计入“连聊四条”需明确，优先按用户消息计连聊、戳击仅更新互动；恢复后的时间窗口也应遵循相同语义。
- 保留现有六情绪、粘性切换和人格基调，不借机重做人设或整个情绪算法。

验收：假时钟验证超过 90 秒的旧互动不触发 burst；自主推力不改用户互动时间；连续两回合第二回合无标签不会复用第一回合；重启恢复不产生过期连聊。

## 4. 第二优先级：让工具和交互形成可用闭环

### U01｜任务控制与输入不丢失

位置：`src/renderer/js/chat.js`、`main.js`、`index.html`。

修改要求：

- 增加可发现的“停止任务”入口，连接 S04，不能把停止 Live2D 动作当作停止任务。
- 忙碌时保留草稿，提供“停止并发送”等明确操作，不能无提示忽略用户的新指令。
- Enter 发送检查 `isComposing` 等输入法组合状态，避免中文选词误发。
- 检查 `chat.send()` 返回的 `{ok:false,error}`，不能只处理抛异常；后端拒收时保留或恢复输入，并准确显示是否发送成功。
- 用户翻看历史时不强制滚到底部；接近底部才自动滚动，否则显示新消息提示。
- 桌宠短回复在完成后保留一段可读时间；当前 DONE 立即隐藏气泡需调整。工具阶段文本与最终回答清晰区分。

验收：中文输入法、连续发送、语音识别结束时已有任务、跨窗忙碌、发送拒收、长回复翻阅、桌宠短回复均有场景验证。

### U02｜统一确认面板的生命周期

位置：`src/renderer/js/ui.js`、`chat.js`、`src/main/agent.js`、窗口编排。

修改要求：待确认时桌宠有明确提示并可打开面板；显示对象、动作、必要参数和超时状态；超时、取消、另一窗口已处理时立即失效。主进程为唯一事实来源，按钮不能一直有效。

验收：仅桌宠、双窗存在、切换形态、30 秒超时、取消、另一窗口先确认、连续确认均无残留或误确认。

### T01｜结构化工具结果充分回喂

位置：`src/core/agent/json-protocol.js` 的 `formatToolResult()`、Agent Loop、各工具。

问题：统一回喂仅用 summary，丢失 `data` 中有用内容，例如浏览器链接、文件正文剩余部分。`file_read` 最多读 64KB，但 summary 仅含前 4000 字符，模型看不到余下正文。

修改要求：

- 保留统一结果封装，支持 `ok/status/summary/data/artifacts/truncated/errorCode` 等必要字段，不要求每个工具填满。
- 工具专属序列化明确哪些字段给模型、哪些给界面，设置总输出预算；不直接无界 stringify 全量结果。
- 文件读取返回范围、总量及续读位置；浏览器返回来源 URL、相关链接和观察信息。
- 失败结果标注原因与恢复路径；副作用可能已发生时，禁止无条件自动重试。

验收：模型在第二步能使用 summary 之外的必要字段；长结果可继续读取；失败、截断、空结果不混淆。

### T02｜浏览器“观察—动作—验证”闭环

位置：`src/core/tools/browser.js`、`registry.js` 及工作台工具卡。

问题：模型主要看到正文，却需要提供 CSS selector，容易猜选择器；缺少任务级标签页管理、用户接手和动作后验证。

修改要求：

- 增加轻量页面观察：URL、标题、可见的按钮/链接/表单控件及 accessible name，分配短期元素 ID。
- 动作优先用观察获得的元素 ID；映射在页面变化时失效，陈旧 ID 必须重新观察，不点击猜测对象。
- 为任务明确选用标签页，初期可默认新开任务页，避免直接覆盖用户正在使用的最后一个标签页。可显示 CDP/托管模式及当前 URL。
- 动作后检查导航、弹窗或可见状态变化；把“点击已触发”和“任务已完成”分开。
- 登录、验证码、文件选择、权限弹窗等不可自动完成时，提供“需要你接手→完成后继续”，不要无休止重试。
- 与 S02 共用风险决策，不让新工具路径绕过确认。

验收：本地测试页面覆盖填表、点击、异步更新、页面重排、失败提示、导航、弹窗、用户接手；至少一个多步骤任务不依赖编造 CSS。

### T03｜截图真正接入视觉模型

位置：`src/main/native-tools.js`、LLM 消息构建、工具结果封装和界面。

问题：截图现在只保存 PNG 并返回路径；模型没有收到图片，不能据此看屏幕。

修改要求：

- 用户可选屏幕或区域并预览；发送前明确所选图片，默认不要多屏全量上传。
- 支持视觉的提供商通过正确的图像消息格式接收图片。避免图片被历史文本归一化逻辑丢弃。
- 不支持视觉时明确提示，不生成“已看到”的虚假回答；不擅自更换服务上传图片。
- 截图产物有预览/打开/复制入口和临时文件清理策略；控制尺寸、数量和资源占用。

验收：用含唯一测试文字或图形的本地图像验证模型实际接收图片；不支持视觉、取消发送、多屏、过大图片均有明确反馈。暂缺支持视觉的集成条件时，保留明确的未验证项，不能只凭返回文件路径判定完成。

### T04｜补齐高频文件操作及结果交付

位置：`src/core/tools/files.js`、`registry.js`、renderer 工具卡和受限的产物 IPC。

修改要求：

- 先增加文件名/内容搜索、按行读取、带原文匹配校验的局部修改。
- 增加常用重命名/移动能力，提供预览及冲突处理；覆盖操作按 S02 提供确认或备份。
- 操作冲突、原文不匹配、文件被外部修改时停止并报告，不能盲目整文件重写。
- 交付文件可打开、显示位置、复制路径；修改文件可查看差异和恢复备份；网页来源可点击；截图可预览。
- 打开产物的 IPC 只接受已登记或核验的文件/URL，不直接把模型任意字符串交给 shell。
- PDF/Office 解析作为后续可选项，不强制加入本轮核心范围。

验收：临时目录完成“查找目标→局部修改→查看差异→打开结果→恢复”，验证路径边界、目标不存在、重名和外部修改冲突。

### T05｜正确表达任务进度、失败与完成

位置：Agent Loop、统一工具结果、工具卡和最终回复。

修改要求：

- 区分思考、待确认、执行中、需要用户接手、部分完成、失败、取消和完成，不让错误后仍显示成功。
- `open_app` 的启动请求与应用可用、浏览器点击与业务完成、通知调用与用户已读分开表达。
- 触发步数上限、超时或错误时汇报已完成项、未完成项和可继续的下一步，不能仅输出笼统“先停在这里”。
- 检测明显重复失败，提供有限恢复策略；仅对明确可安全重试的操作重试，涉及提交/写入时先查实际结果。
- 单轮模型调用步数之外限制工具总次数、输出与耗时；避免一次返回大量调用绕过预算。

验收：本地可控工具失败、重复失败、部分成功、超时、步数耗尽和取消后，用户能准确判断做到了哪一步，不会收到虚假的成功结论。

### U03｜会话历史可见且可切换

位置：`src/main/persist.js`、`agent.js`、preload IPC、renderer。

问题：“新对话”实际清空历史，不是多会话；历史可被模型恢复，但界面没有相应读取入口。

修改要求：增加轻量会话 ID、标题、消息及产物引用；可新建、切换、恢复、删除，长期记忆继续共用。恢复消息时不重放工具、不重新弹确认、不重新朗读。与 D02 一起保证运行中切换不会串话。

验收：重启恢复、两会话切换、旧回合晚到、历史中的失败/取消/工具结果均准确；不扩展为多用户聊天平台。

### U04｜提醒支持送达反馈与稍后提醒

位置：`src/main/reminders.js`、`agent.js`、提醒面板、通知适配器。

问题：当前到点广播后一次性提醒直接标记完成，未区分已触发、用户已看到和已处理；提醒路径没有接上已有系统通知工具。隐藏窗口或用户离开时可能错过。

修改要求：

- 记录已触发与用户处理状态，提供“稍后提醒”“已完成”及未读提醒列表；重复提醒的单次处理不得误取消后续重复。
- 窗口隐藏时可发系统通知，通知失败不伪装送达；显示设置中勿扰与重要提醒的实际规则。
- 自然语言创建后回显完整日期、当地时间和重复规则；歧义较大时澄清，不静默猜测。
- 过期提醒保留可查看状态，避免自动作废后用户无从发现。明确应用关闭时不能定时提醒；如保留该限制，在界面说明，不宣称系统级闹钟。

验收：前台、后台、隐藏、勿扰、应用重启、错过提醒、多条同时到期、稍后提醒和重复提醒均验证；提醒只登记一次，不因恢复重复轰炸。

## 5. 第三优先级：语音、记忆演进与兼容性

### V01｜唯一播放者和统一语音打断

位置：`src/renderer/js/voice.js`、`main.js`、窗口编排、语音服务。

待验证：桌宠窗和工作台窗都初始化语音并订阅同一 DONE/PET 广播，没有看到唯一播放者仲裁。窗口 `hide()` 不触发 `beforeunload`，不能依赖它清理隐藏窗播放。

修改要求：先双窗实测并记录结论，再建立明确的唯一播放者；切换形态不重复合成、播放或继续录音；用户开始说话时停止旧朗读。区分“停止朗读”和“停止任务”，重要提醒与普通回复有明确的抢占/排队规则。ASR 结果提供可编辑草稿，自动发送可配置。

验收：单窗、双窗、切换形态、隐藏窗、连续回复、提醒插入、录音中切窗、用户打断、识别错字修正均不串音、不丢指令。

### V02｜从模型增量输出开始按句 TTS

已确认：当前在 Agent DONE 后才 `speak(evt.text)`，按句合成尚未覆盖模型生成阶段的等待。

修改要求：复用现有 segmenter，接收适合朗读的增量文本，完整句子成形后开始合成；过滤情绪标签、JSON 工具协议等；限制队列并处理取消；DONE 不重复朗读已播放部分。原生工具通道和 JSON 兜底分别处理，不能为低延迟朗读协议垃圾。

验收：使用可控延迟的假模型证明首句在 DONE 前开始合成；真实 TTS 验证取消、降级、句序和口型；分别记录模型首 token、首句、合成与播放时间，不给未经测量的“一秒首响”承诺。

### M01｜在 RAG 前补齐记忆数据约束

位置：`src/core/memory.js`、`src/main/persist.js`、抽取服务与上下文构建。

修改要求：

- 模型抽取、手动新增、磁盘加载走统一数量、文本长度和类型校验；“每轮最多两条”落实到代码。
- 同时限制存储容量和提示 token 预算，不能只限制条数；导入的脏数据也适用。
- 对身份、偏好、约定等建立必要的事实键、重要性、有效期或归档语义，避免只按 FIFO 挤掉重要事实；处理新旧偏好冲突。
- 异步抽取按来源顺序或版本提交，避免旧回合晚到覆盖新事实。删除后旧抽取不能无提示复活。
- 保留检索接口，先用相关性、重要性和近期性筛选。已有 RAG 计划可在此接口后接入，不要求立即部署向量数据库。

验收：数量超限、超长文本、手动与加载绕限、冲突更新、乱序回调、删除后回调、重要记忆保留、提示预算均有测试。不要仅凭召回率宣称记忆安全或事实正确。

### C01｜本地提供商、搜索与能力状态准确

位置：`src/main/agent.js`、LLM provider 配置、`src/core/tools/search.js`、设置页。

修改要求：

- API Key 是否必需按提供商能力判断。无密钥 Ollama 不应因全局 `hasKey` 判断进入 Mock；有鉴权的本地实例仍应支持配置。
- 展示当前实际大脑与降级原因；已配置与可用分开，不把 Mock 回复伪装成模型成功。
- 工具/视觉/流式能力按实际配置和已知能力判断，避免仅靠品牌名；协议不支持时给出可理解的反馈。
- 搜索区分无结果、解析失败、网络超时和服务限制；保留来源链接。HTML 抓取仍可保留，不强制换付费搜索服务。

验收：无 Key 本地模型实际收到请求；不可达或协议不兼容时准确反馈；搜索页面样例、空结果和网络错误有验证。

## 6. 实施批次与范围控制

按以下顺序完成，每批保持可运行，提交清晰的变更记录；有 Git 时使用独立、可审阅的提交，不擅自推送或发布。

| 批次 | 任务 | 结束条件 |
|---|---|---|
| A：执行边界 | S01–S06 | 免确认绕过、路径越权、取消后执行等核心问题关闭；重要边界测试通过。 |
| B：状态可靠 | D01–D03、M01 的数据校验和顺序提交部分 | 满额记忆正确落盘，新对话不被旧回调覆盖，情绪不复用过期事件。 |
| C：日常任务闭环 | U01–U02、T01–T05、C01 | 用户能控制任务，浏览器能观察操作，结果能直接使用，失败有交代。 |
| D：持续使用体验 | U03–U04、V01–V02、M01 剩余部分 | 历史可见、提醒可处理、语音有唯一播放者及真实增量首响，记忆检索有预算。 |

结构调整只在确实帮助这些任务时进行：把 `agent.js` 中独立的记忆抽取、会话存储、主动行为服务提取出来即可。IO 适配器可以逐步整理到 `main/adapters` 或 `infra`，不要求一次搬完；不得为目录“好看”扩大改动。

本轮默认不包含：重写 UI 框架、复杂 DAG 调度器、多 Agent 系统、多用户/云端账号系统、完整电脑视觉控制、必须部署的向量数据库、剧情创作、模型重做、商业化改造。

## 7. 核心端到端验收场景

### 场景一：查资料并交付文件

用户：“帮我查一下某主题，整理成一份带来源的 Markdown，保存到授权目录并打开。”

验收：

1. 看到任务开始和当前步骤，输入草稿不丢失。
2. 搜索来源可点击；浏览器按实际页面观察操作，不猜不存在的 selector。
3. 内容与来源对应；遇到失败明确说明，不编造已读取内容。
4. 文件写入正确目录；覆盖现有文件需按策略确认或备份。
5. 交付卡提供打开、显示位置、复制路径；修改可查看差异和恢复。
6. 中途取消后未开始步骤不执行，已发生操作准确汇报。
7. 重启后能看到会话与交付记录，不重放工具或重新朗读。

### 场景二：桌宠语音与提醒

用户从桌宠语音设置提醒，切到工作台继续对话，提醒到点时窗口处于隐藏或后台。

验收：识别结果可纠正；创建时间回显明确；双窗不重复朗读；提醒可见、可稍后处理；提醒与对话有确定优先级；用户打断时无残留录音或旧播放；无法保证的关闭应用提醒能力明确说明。

### 场景三：边界与恢复

在隔离环境模拟命令拼接、授权目录链接、确认期间取消、文件写入失败、满额记忆更新、新会话期间旧任务返回、两回合情绪标签缺失。

验收：所有危险副作用被阻止或经正确确认；无串话、无旧确认复活、无虚假成功；数据可恢复，错误信息对用户可理解。
