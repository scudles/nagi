## 3. 各项实现方案

### A. B23 外部便签写入安全桥接（唯一契约硬缺口）

**目标**：她留下的便签可以真的变成一个文件，落在您亲自指定的文件夹里（例如「凪的角落」），默认关闭。

**做法（严格走已有安全边界，不新造机制）**：

1. `core` 层（纯逻辑，可单测）：在 `src/core/presence/` 下新增 `notes-file.js`——只做三件事：**路径归属校验**（目标必须在已授权根目录内、拒绝 `..` 穿越/符号链接/非授权路径）、**文件名与内容规范化**（日期前缀、长度截断、不做字符替换把戏）、**去重与配额**（同一便签只写一次、每天上限沿用便签的 3/天 + 30 分钟间隔）。
2. `main` 层：不新开 IPC，复用现有**文件工具的安全策略与逐次确认流**（原生目录授权 + 每次写入弹确认），**不在订阅回调里直接 `fs` 写桌面**（契约 §4 明令禁止的写法）。
3. 设置页：新增「把便签写到文件夹」开关，**默认关闭**；打开时引导您选一个授权目录；未授权时界面如实显示「未授权」而不是假装成功。
4. 渲染层：便签卡片上标出「已保存到 / 仅应用内」两种状态，她归来提便签时措辞与状态一致（不谎称写过文件）。

**验收**：
- 单测：越权路径（授权根之外、`..` 穿越、符号链接）必须被拒；未授权时返回拒绝且不落盘；同名/同内容去重；配额生效；关闭开关即清空（沿用便签现有「关闭即删文件」语义）。
- 真机：走一遍「打开开关 → 选目录 → 离开 → 回来 → 文件夹里真有便签文件 → 逐次确认弹窗正常」。

**风险与对策**：这是**系统级写操作**，风险最高。对策是默认关闭 + 逐次确认 + 只写授权目录 + 单测把越权全挡住；任何一步不放心就停在应用内形态。

**工作量**：中等（core 纯逻辑少、main 接线与安全边界测试占大头）。
