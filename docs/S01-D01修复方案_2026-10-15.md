## 1. S01 修复方案

### 1.1 设计决策

任务书给了两条路：(a) 彻底移除免确认；(b) 保留受控免确认映射。**选 (b)**，理由：

- 产品体验：凪 是主动型助手，对话里「看看现在有哪些进程」「网络配置发我」是合理只读场景，全部弹确认会把主动行为变唠叨。
- 任务书明确认可该路径（"如果保留免确认能力，使用受控操作到固定可执行文件的映射"）。
- 实现成本可控：一张小映射表 + 元字符校验 + `execFile`。

三条不可放宽的行为约束：

1. **模型永远只能指定「受控命令 + 受限参数」，不能指定可执行文件本身。**
2. **凡不在受控映射内的命令串，一律 HIGH 确认**，走原 `exec()` 完整 shell（保留"帮我跑个命令"的核心场景能力）。
3. **`confirmHighRisk` 开关整体移除**，HIGH 一律确认；黑名单保持"命中即永久拒绝"，但文档与注释不再宣称它是沙箱。

#### ① `src/core/safety/policy.js` —— 删白名单免确认，新增受控命令计划

新增：

```js
/**
 * 受控只读命令映射：模型可免确认执行的唯一入口。
 * 键 = 规范化后的完整命令前缀；win = Windows 实际 argv（shell:false 执行）。
 * 模型只能选键、加"受限参数"，不能指定可执行文件。
 */
const SAFE_COMMANDS = {
  dir:       { win: ['cmd.exe', ['/c', 'dir']] },
  ipconfig:  { win: ['ipconfig', []] },
  tasklist:  { win: ['tasklist', []] },
  systeminfo:{ win: ['systeminfo', []] },
  where:     { win: ['where', []] },
  ver:       { win: ['cmd.exe', ['/c', 'ver']] },
  'node -v': { win: ['node', ['-v']] },
  'npm -v':  { win: ['npm', ['-v']] },
  'git status': { win: ['git', ['status']] }
}

/** 受限参数：仅字母数字与路径字符，禁空格/通配符/引号/一切元字符 */
const SAFE_ARG = /^[A-Za-z0-9_\-./:]+$/

/** shell 元字符（cmd 与 bash 交集）：出现即无免确认资格 */
const SHELL_META = /[&|;<>`$(){}[\]*?~^!'"\n\r]/

/**
 * 生成受控执行计划；不返回 null 之外的"部分通过"。
 * @returns {{file:string,args:string[]}|null}
 */
export function planSafeCommand(cmd) {
  const s = String(cmd || '').trim().replace(/\s+/g, ' ')
  if (!s || SHELL_META.test(s)) return null
  const lower = s.toLowerCase()
  for (const [key, spec] of Object.entries(SAFE_COMMANDS)) {
    if (lower === key) return { file: spec.win[0], args: [...spec.win[1]] }
    if (lower.startsWith(key + ' ')) {
      const rest = s.slice(key.length + 1).split(' ')
      if (rest.length && rest.every((t) => SAFE_ARG.test(t))) {
        return { file: spec.win[0], args: [...spec.win[1], ...rest] }
      }
    }
  }
  return null
}
```

`needsConfirm` 改写（删除 `confirmHighRisk` 相关分支与 `isWhitelistedCommand` 调用）：

```js
export function needsConfirm(call, opts = {}) {
  const risk = getToolRisk(call.name)
  if (call.name === 'run_command') {
    if (isCommandBlocked(call.args?.command)) return { confirm: true, blocked: true, risk }
    const safe = planSafeCommand(call.args?.command)

    return { confirm: true, blocked: false, risk: RISK.HIGH } // 其余 shell 命令一律确认

  if (risk === RISK.HIGH) return { confirm: true, blocked: false, risk } // 不再有开关
  if (opts.allowedTools && !opts.allowedTools.includes(call.name) && risk !== RISK.LOW) {
    return { confirm: true, blocked: false, risk }
  }
  return { confirm: false, blocked: false, risk }
}
```

#### ② `src/core/tools/system.js` —— 新增受控执行路径

```js
import { exec, execFile, spawn } from 'node:child_process'
const execFileAsync = promisify(execFile)

// run() 签名扩展第二个参数；decision.safe 存在时走 execFile(shell:false)
async run(args, opts = {}) {
  const command = String(args.command || '').trim()
  if (!command) return { ok: false, summary: '缺少 command 参数' }
  const timeout = Math.min(Math.max(Number(args.timeoutMs) || 30000, 3000), 120000)
  const t0 = Date.now()

  if (opts.safe) {
    // 受控路径：固定可执行文件 + 校验过的 argv，不过 shell
    try {
      const { stdout, stderr } = await execFileAsync(opts.safe.file, opts.safe.args, {
        windowsHide: true, timeout, maxBuffer: 1024 * 1024,
        cwd: resolveCwd(args.cwd, cfg.cwd)   // 见下方约束
      })
      return okResult(command, stdout, stderr, t0)
    } catch (err) { return errResult(command, err, t0, timeout) }
  }

  // 高风险路径（仅在校验/确认后到达）：维持完整 shell 能力
  try {
    const { stdout, stderr } = await execAsync(command, { cwd: args.cwd || cfg.cwd || undefined, timeout, windowsHide: true, maxBuffer: 1024 * 1024 })
    return okResult(command, stdout, stderr, t0)
  } catch (err) { return errResult(command, err, t0, timeout) }
}
```

cwd 约束（任务书"限制 cwd"）：`resolveCwd(requested, fallback)` —— 若 `cfg.fileRoot` 已配置，`requested` 必须过 `isPathWithin(cfg.fileRoot, requested)` 否则拒绝执行；未配置 `fileRoot` 时忽略模型请求的 cwd，用 `fallback`。需要从 settings 把 `fileRoot` 传进 `createSystemTools(cfg)`（接线见 ⑤）。

`okResult` / `errResult` 为现有两个分支结果的抽取复用，返回结构不变（`{ok, summary, data, ms}`）。

## 2. D01 修复方案

### 2.1 设计决策

根因是"以数量判断变化"。任务书要求"按内容变化或 dirty/version 判断写盘；返回真实新增/删除结果"。

**把判断逻辑下沉为纯函数**（`core/memory.js`），`main/persist.js` 只做 IO——这样满额淘汰、去重跳过、删除不存在条目都能被单测覆盖，不必 mock electron（现有测试目录无 persist 测试，正是这个原因）。

`applyMemoryOps` 的导出签名与返回（数组）**保持不变**，`removeMemory`、`memory.test.js` 六处用例零改动；新函数与之并存。

### 2.2 代码草案

#### ① `src/core/memory.js` 新增 `mergeMemoryEntries`

```js
/**
 * 合并增删指令并报告真实变化。纯函数。
 * @returns {{entries:Array, changed:boolean, added:string[], removed:string[]}}
 *   added  = 实际进入清单的新文本（去重跳过/超限淘汰的不算）
 *   removed = 实际被删掉的旧文本
 */
export function mergeMemoryEntries(entries = [], ops = {}, now = Date.now()) {
  const norm = (s) => String(s || '').replace(/\s+/g, '').trim()
  const removeSet = new Set((ops.remove || []).map(norm))
  const removed = entries
    .filter((e) => e && typeof e.text === 'string' && removeSet.has(norm(e.text)))
    .map((e) => e.text.trim())
  let out = entries
    .filter((e) => e && typeof e.text === 'string' && e.text.trim())
    .filter((e) => !removeSet.has(norm(e.text)))

  const seen = new Set(out.map((e) => norm(e.text)))
  const added = []
  for (const text of ops.add || []) {
    const n = norm(text)
    if (!n || seen.has(n)) continue
    seen.add(n)
    const entry = { id: 'm' + now.toString(36) + '_' + out.length, text: text.trim(), at: now }
    out.push(entry)
    added.push(entry.text)
  }

  const beforeLimit = out.length
  if (out.length > MEMORY_LIMIT) out = out.slice(out.length - MEMORY_LIMIT)
  const changed = JSON.stringify(entries) !== JSON.stringify(out)
  return { entries: out, changed, added, removed }
}
```

`applyMemoryEntries` 与 `applyMemoryOps` 二选一落地（推荐前者，后者改为委托以保兼容）：

```js
export function applyMemoryOps(entries = [], ops = {}, now = Date.now()) {
  return mergeMemoryEntries(entries, ops, now).entries
}
```

#### ② `src/main/persist.js` 的 `mergeMemoryOps` 改写

```js
export function mergeMemoryOps(ops, now = Date.now()) {
  loadMemories()
  const before = memories
  const r = mergeMemoryEntries(before, ops || {}, now)
  memories = r.entries
  if (r.changed) persistMemories()   // 内容变化才写盘：满额淘汰也会落
  return { before: before.length, after: memories.length, added: r.added, removed: r.removed }
```

## 4. 风险与回滚

| 风险 | 缓解 |
|---|---|
| `execFile` 与 `exec` 错误对象形态差异（`err.code` 语义） | `errResult` 统一封装，返回结构不变；mock 测试锁定 |

| 受控表过保守影响体验 | 表可增量扩充；扩充时逐项过 `SHELL_META` 评审，不放行任何带元字符的键 |
| 满额写盘频率 | 防抖 400ms 未变；写盘内容为全量 memory.json（≤60 条，KB 级），无压力 |
| 回滚 | git 单提交回滚；无数据格式变更（memory.json 结构不变），回滚不丢数据 |
