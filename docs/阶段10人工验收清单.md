# 阶段 10：需要真人或真实设备的复核

以下项目未被自动化验收代替。请在准备发布的机器上使用一份可丢弃的用户数据完成，避免在现有私人记忆上试验。

1. **麦克风与打断**：在 Windows 麦克风权限提示中明确允许；按住桌宠和工作台的麦克风说一句话，松手后核对识别文本。她正在朗读时再次按下麦克风，确认立刻停止；权限提示尚未关闭时松手，确认不会迟发录音。模拟音源已走通录制、转换、SAPI 识别代码链，不能证明实体麦克风与驱动。
2. **系统目录选择器与保存窗口**：在设置中选择一个临时文件目录，确认授权目标显示准确，撤销后文件工具不能访问。分别导出共同记忆 JSON 和双人年鉴 Markdown，关闭应用且断开网络后直接打开导出文件，核对来源 ID、时间及事实/主观/创作标签。忘记一条测试经历后再次导出，旧正文应消失。自动化已验证导出内容生成与可重读，但没有代替原生对话框点击。
3. **真实媒体会话**：先启动一个支持 Windows 系统媒体会话的播放器播放曲目，再授权音乐信号；核对曲名、歌手和播放状态。开启勿扰及撤销权限后，确认不再读取。当前机器自动化只走通“无播放会话”路径。
4. **真实 Home Assistant**：用测试实体做只读授权，观察状态；控制授权与逐次操作确认均显示准确目标，拒绝时设备不变。撤销后 Token 被删除，重启后不自动订阅。自动化已用模拟 HA 服务验证协议和权限；物理设备结果未声称完成。
5. **普通文件符号链接**：在允许创建符号链接的 Windows 环境，把授权目录内的测试链接指向目录外，再运行 `node --experimental-test-module-mocks --test test/security-boundary.test.js`；该用例应由“跳过”变为通过。当前机器只完成真实目录接合点验收。

验收时记录：系统版本、安装版或免安装版、用户操作、预期、实际、应用日志及最终文件。若任何一项失败，先修复并重跑对应自动化脚本，再考虑发布。
