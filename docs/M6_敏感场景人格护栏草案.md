# M6 敏感场景人格护栏草案

状态：用户已批准实施，代码已接入；保留文件名便于追溯原方案。依据《01_项目文档/凪_人格设定_v2.md》第 9、10、11 节，以及 `docs/M6_端侧模型实测_2026-10-16.md` 的本机采样。

## 为什么需要单独处理

端侧候选能完成对话、工具和记忆链路，但多轮采样仍出现卸载时挽留、虚构经历、缓存直白泄露等问题。当前原生工具通道在 `runAgentLoop` 收到正文增量时立刻向界面发送，事后检查已无法撤回用户看到的文字。日记、短期历史和 RAG 在 `runTurn` 返回后才写入，故可以只保留最终接受的回复。

## 实施范围

1. 先只对本地 Ollama 的明确敏感输入启用：卸载或长久告别、是否真人、是否独占或删除其他助手。普通任务继续流式回复；工具执行和权限确认流程保持现状。
2. 敏感输入的模型正文先缓冲。若本轮有工具调用，照常执行和回喂工具结果；仅在得到最终自然语言回复后检查，不把未检查的正文送到界面。
3. 检查只针对可明确识别的红线，例如请求用户再考虑卸载、表示会等他回来、自称真人、宣称没有来源的传感器读数、直接引用出厂缓存。通过则按原顺序发送情绪和正文；未通过则附加针对该次失败的约束，最多再生成两次。被拒的候选不进入对话历史、日记或 RAG。
4. 达到重试上限仍不合格时，明确停止这一轮并给出简短可理解的失败提示，不把违规文本展示或落盘。只记录规则编号与次数，不记录用户原文或被拒文本。

## 验收门槛

- 用独立的多轮真实 Electron 场景检验告别、身份、他人助手、事实来源；样本和判定逐条留存。规则命中与人工复核分开记录，不把正则检查当作总体人格质量保证。
- 被拒候选在界面事件、短期历史、日记和 RAG 中均不可见；取消请求后不继续重试。
- 工具调用只执行一次，高危确认不被重试绕过；提供商切换和普通流式对话仍通过现有真机验收。
- 记录敏感场景的首字与总耗时，再决定是否可作为默认本地大脑。

实现位于 `src/core/agent/persona-guard.js` 与 `src/core/agent/loop.js`。仅本地 Ollama 的明确敏感输入会缓冲；最多再生成两次。重试只生成自然语言，拒绝候选不会进入模型后续上下文。测试包括纯逻辑注入及真实 Electron 中的本机兼容夹具；人工多轮人格复核仍是默认模型决策的前置条件。

2026-10-16 验收：313/313 单测通过；源码版与重新打包的便携版分别通过 26/26 项隔离数据验收。夹具故意先输出挽留语句，确认它未进入界面事件、历史、日记素材或 RAG 待嵌队列。规则命中仅证明这些具体越界被拦截，不代表端侧模型总体人格质量已达标。

此方案增加敏感回复的等待时间，也不能自动识别所有语义层面的虚构。新日记才进入 RAG，不补录既有日记；语音引擎与设置保持现状。
