# modelHint 同轮裁决时序（供绿区与作者评审；本轮不实施）

## 裁决点

`buildMessages` 在模型请求前已经写入本轮 system 意图约束。模型在这次请求中产出的 `modelHint` 无法回到该时点；把它存到**下一用户轮**会错配用户输入，禁止。这里的“下一轮”只能是**同一用户 turnId 内的一次受限重写尝试**。

## 建议流程

1. `buildMessages` 先按危机、用户明确要求、确定性澄清规则裁决硬约束；其余轮次用默认意图组成首请求。一次请求同时返回候选正文和可选意图标签，不新增分类请求。
2. 流归一化只解析有界的开头标签。编排层缓冲候选正文，在最终回复出站前，将合法 hint 连同 `turnId/epoch/step` 交给 `resolveIntent`。工具调用步的 hint 不作为最终回复意图；危机和用户明示约束永远优先。
3. 若候选正文已符合最终意图约束，直接交付，总模型调用数为 1。若合法 hint 改变默认意图且正文不符合新约束，只在**同一 turnId** 内用裁决后的指令重写一次；重写产物仍过统一 persona/危机护栏。至多 2 次请求，第二次失败走既有失败路径，不展示未审候选。
4. hint 是单轮临时值：消费后清零；取消、超时、工具步结束、换 turnId/epoch 或最终出站后丢弃。不得写入长期 mood、历史消息或进程全局 `lastHint`，也不得在下一用户轮的 `buildMessages` 前取出使用。

## 实施边界与验收

- 待蓝区 D1 合并后再改 `agent.js`、`stream-normalize.js` 和必要的 loop 事件透传；本轮 `loop.js`、`agent.js` 均不改。
- 测正常一次请求、同轮重写至多一次、显式求安静与模型 `solve` 冲突、危机覆盖 hint、非法/迟到标签、工具多步、取消及两个 turn 交错。断言同轮 ID 绑定、无下一用户轮继承、无新增分类网络调用，正文和意图日志同源。
- 如果评审要求“模型建议必须影响**首请求**的 system 指令”，在不增加前置模型请求的条件下不可实现；需调整契约为“同次输出候选，经编排层复核或同轮重写”。
