## 1. 这是什么

**凪 Nagi** —— 一个住在 Windows 桌面上的 Live2D 智能助手（个人自制、非商用）。

形态：透明置顶的桌宠（Live2D 模型站在屏幕一角）+ 可展开的工作台（对话、日程、便签、设置）。
能力：接 LLM 对话、调工具（浏览器/文件/程序）、控制 Home Assistant 智能家居、语音朗读、记住用户。

技术上它不是一个"聊天外壳"，而是一个**状态机密集的实时渲染 + 本地服务**混合体：
- 渲染层有 12 个 `beforeModelUpdate` 钩子层叠在同一个 Live2D 模型上（姿态/呼吸/眨眼/表情/口型/转向/纵深/微动…）
- 主进程有会话、工具执行、持久化、媒体与前台窗口感知、提醒、RAG 记忆
- 两层通过 6 份 `src/shared/*-protocol.js` 契约通信

## 3. 怎么跑（如果你想验证结论）

```bash
npm install                 # postinstall 会去下载 Cubism Core（需要网络）
npm run build               # electron-vite build
npm test                    # 必须 Node >= 24；Node 22 会让 7 个 electron mock 测试假失败
npm run verify:frame        # 真机验收：起一个隔离实例，用 CDP 读回渲染结果
```

⚠️ 两个环境坑（**很容易被误判成代码 bug**）：
- 跑任何 `verify:*` 前必须 `NAGI_RENDERER_SANDBOX=0`，否则 GPU 进程崩溃（`exit_code=-1073741819`），桌宠页永远 ready 不了，表现是"脚本卡住/找不到页面"。
- 改完代码必须**完全退出进程再启动**（托盘常驻 + 单实例锁），否则看到的还是旧画面。判新旧：`%APPDATA%\凪 Nagi\boot.json` 的 `startedAt` vs `out/renderer/assets/*.js` 的 mtime。

**本包不含模型二进制**，所以 `npm test` 里依赖真实模型的少数用例、以及全部 `verify:*` 都会失败——这是预期行为，不是缺陷。

## 4. 这个项目在乎的两条不变量

审查时如果把这两条当"过度设计"删掉，会连带破坏一堆东西：

1. **分层隔离**：`core/` 不许 import electron、不许碰 DOM、不读 `Date.now()`（时间由调用方注入）。
   好处是"位移/缩放/取值范围/过渡时长/有无跳帧"这类东西能被单测钉死；代价是参数要层层透传。
2. **钩子层的让位纪律**：`beforeModelUpdate` 链上，用 `set` 写绝对值的层会**覆盖**前面用 `add` 写增量的层。
   所以"谁让位给谁"必须显式写，而且**让位不能硬切**（`if (active) return`），要按包络 `keep = 1−w` 交叉淡变，否则切换帧会从满幅跳到 0。

## 5. 已知不足（先看这里，别重复报告）

这些是作者自己已经知道、并记录在案的，欢迎挑战判断，但不必当"新发现"：

### 5.1 结构
- **两个 God file**：`src/renderer/js/live2d.js` **2398 行**、`src/renderer/js/main.js` **3317 行**。
  前者混了模型加载、12 个钩子、取景计算、快照、调试接口；后者混了所有面板的 DOM 逻辑。
- **钩子链顺序是隐式的**：12 层按注册顺序执行，覆盖关系靠注册先后决定，没有显式的排序/优先级机制。
  加一个新层时必须知道它该插在哪，否则静默失效（历史上多次踩）。
- **无类型检查、无 lint**：纯 ESM JavaScript，没有 `.ts`、没有 eslint/prettier 配置，31k 行全靠测试兜底。

### 5.2 错误处理
- **236 处 `} catch {` 空实现**（`grep -rn "} catch {" src/ | wc -l`）。多数是"模型缺参数就跳过"这类合理降级，
  但也可能掩盖真实故障——这是本次审查最值得逐个过一遍的地方。

### 5.3 验证体系
- **验收脚本容易腐烂**：`verify-*.mjs` 里曾经硬编码期望值（时长、幅度、周期），改了参数以后脚本假失败。
  已经四次出现同类问题（`docs/DECISIONS.md` 里 D40 记着"验收脚本自己会烂"）。现在部分已改为从配置实读，但**没有强制机制**。
- **全量测试有环境噪音**：本机批量删除会撞安全守卫（阈值 50），导致 5~9 项偶发失败，隔离复跑必过。
- **`models/` 被 `.gitignore` 排除**：模型侧的精确数值（表情肌肉向量、取景比例）只能写进文档，
  代码与文档之间**没有自动校验**，容易漂移。

### 5.4 安全
- 工具执行（打开程序、写文件）有路径白名单与确认流程；
  但 `docs/TASKS.md` 明确记着 **FIX-2（外部进程替换的 TOCTOU 竞态）未修**，理由是"未复现，不宣称安全"。
- 外部便签写入是全项目**唯一一处 fs 写盘**，默认关闭，每次写入弹原生确认。

### 5.5 可观测性
- **没有统一日志文件**（README 自述）。主进程日志在终端、渲染日志在 DevTools，
  排查线上问题只能靠临时加日志 + 重启。

## 8. 建议的审查角度（按性价比排序）

1. **钩子链**：12 层 `beforeModelUpdate` 的覆盖/让位关系，能否用更显式的机制（优先级声明、中间件栈）替代注册顺序？
   现有实现里，"谁 set 谁 add、谁该让位"只写在注释里，代码层面没有任何约束。
2. **`live2d.js` 拆分**：2398 行里哪些是"模型生命周期"、哪些是"钩子"、哪些是"调试接口"？
   拆分时最容易破坏的是钩子注册顺序。
3. **236 处空 catch**：哪些是真降级（模型缺参数）、哪些会把 bug 吞掉？建议逐个分类，而不是一刀切补日志。
4. **验收脚本的设计**：现在 30 个 `verify-*.mjs` 各起一个 Electron 实例，靠 CDP 读回内部状态。
   它们的期望值应该**全部**与配置同源（现在部分还是硬编码），否则改参数就假失败。
5. **测试盲区**：70 个测试文件偏重"向量/状态机"（core 层纯逻辑），
   而 `main/` 的 IO、IPC 边界、持久化失败路径覆盖较薄。
6. **隐私边界**：媒体/前台窗口/活动记录采集了哪些、进了什么上下文、是否落盘、能否一键关闭。
   `docs/实感架构契约.md` 声称有边界，值得对着代码核一遍。
7. **性能**：Live2D 每帧 12 个钩子 + 物理，桌宠常驻。有没有可以省掉的工作？掉帧时会怎样？
